# DSH runtime upgrades

The DSH version card checks the latest published, non-draft GitHub release, including prereleases. It starts a detached, manually requested upgrade and passes the discovered version as `HEADBOT_DSH_TARGET_VERSION`, along with `HEADBOT_DSH_WEB_UPGRADE=1`, to the installation's `bin/update.sh`. The script must install the requested version rather than choosing a fixed npm dist-tag. That script may then proceed while the management page has active connections: it will restart DSH, briefly interrupt browser requests, and restore the same page when the service returns. The page polls every 2.5 seconds while upgrading, retries after a connection drop, and displays the installed version only after the updater confirms it.

The updater script must retain its active-connection deferral for scheduled or otherwise background invocations. Only the exact value `HEADBOT_DSH_WEB_UPGRADE=1` should bypass that check. Validate `HEADBOT_DSH_TARGET_VERSION` as a package version before using it in the install command. The backup, health check, and rollback steps must remain in place for either invocation mode.

On Agent-Mac, the updater script is installed at `~/Applications/DeepSeekHarness/bin/update.sh`, outside the versioned DSH directories. Host-specific edits and validation records belong in `~/Library/Application Support/DeepSeekHarnessMaintenance/` so a future change to the installation layout can be reviewed before repeating them.
